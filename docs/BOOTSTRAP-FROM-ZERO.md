# 从零跑通：ClickUp Skills（Agent 自验证流水线）+ GitHub MCP

## 这份文档是给谁的
给**第一次接触这套系统的人**。默认你不知道它之前怎么搭过，也不知道哪些步骤只是抄文件、哪些步骤必须去读真身、哪些地方只能靠手动截图或 live 证据。

目标不是“看懂概念”，而是：

> 从空白开始，最后真的让它跑起来，而且知道自己哪些地方还没证明。

---

## 0. 一句总原则
这套系统不是“把文档导入进仓库就会活”。

你要分别拿到三层东西：
1. **文件抄本**
2. **live 配置**
3. **证据链**

前两层不等于第三层。

---

## 1. 先准备什么

### 账号
- 一个 ClickUp 工作区
- 一个 GitHub 账号
- 一个可用的 GitHub MCP 连接

### GitHub 权限
- 能建仓
- 能开 GitHub Actions
- 能让 Actions 写 PR / commit 评论
- 如果要跨仓，需要能放 secrets / token

### ClickUp 权限
- 能创建 / 编辑 Skills
- 能创建 / 编辑 Super Agents
- 能给 Agent 配 schedule / trigger / knowledge

### 你要接受的边界
当前仍然不能只靠仓内文件证明：
- skill summary 自动触发
- ClickUp UI-only 字段
- agent 工具在界面上的显示名
- prompt 里的散文在别的仓库改动后是否仍然为真

这些以后要写进 blind spots，不许装作“已经解决”。

---

## 2. 仓库最少要分成哪几类

### A. 共享回写仓
例如 `ci-workflows`。

这里放：
- 共享 `report.yml`
- 它自己的 selftest
- 两条送达路径（PR / commit）
- attest 回头确认评论真的存在

### B. 项目仓
例如小游戏、扩展、网页工具。

这里放：
- 产品代码
- gate
- AGENTS / CLAUDE
- 该项目自己的验证逻辑

### C. 离线备份仓
例如 `anyworkflow`。

这里放：
- 方法论
- 事故台账
- 依赖台账
- 观察者抄本
- blind spots
- 恢复与演练记录

---

## 3. 正确顺序（别反）

### Step 1：先搭共享回写
先让“结论能被读到”。

最低要求：
- PR 评论路径
- commit 评论路径
- 降级评论前置
- attest 送达核对
- shared workflow 自己有 selftest

### Step 2：再拿一个最小项目仓试闭环
优先选：
- 网页小游戏
- 静态网页工具
- 浏览器扩展

别一上来就拿最复杂的仓库。

### Step 3：第一次新对话，只抛对问题
看 `docs/PROMPT-EXAMPLES.md`。

你要观察的不是“它会不会写代码”，而是：
- 会不会先问项目类型
- 会不会先问“跑起来”的判据
- 会不会先搭 gate，再写功能
- 会不会主动把回写和 attest 放进来

### Step 4：绿了还不算，得留证据
至少要有：
- 一条 green PR
- 一次 deliberate red -> green
- 回写评论送达
- 手动写入链路和定时新鲜度分字段
- 真抄本最后一次读回时间

### Step 5：最后再做离线备份仓
因为离线备份仓应该记录**已经被跑通的东西**，不是替你猜未来会怎么搭。

---

## 4. 第一次新对话里，你应该怎么配合

### 它问项目类型时
直接给：
- 这是什么类型（网页 / 扩展 / CLI / Electron）
- “跑起来”的最低判据是什么

### 它问需要你手动开什么时
一次说全，别一轮一轮补。

### 它开始修红时
默认让它自己修。只有三种事你该插手：
- 缺权限
- 缺凭据
- 它根本读不到关键结论

---

## 5. 什么叫“真的跑通了”
不是只有“PR 绿了”。至少要有：

### A. 正向证据
- 真输入会绿

### B. 负向证据
- 故意改坏一次会红

### C. 正向痕迹
- 如果有 heartbeat / schedule，要留下时间戳

### D. 仓外 readback
- prompt / shared workflow / 真文件，至少有最后一次对上真身的时间

---

## 6. 常见失败形状
- 闸门绿，但评论没送出来
- cron 还写在文件里，但其实已经死了
- 抄本和台账都对，但别的 repo 已经变了
- 大文件整文件替换开始咬人
- 观察者开始互相复读，第二条消息变成噪音

---

## 7. 最后一句
如果你照这份文档做，最后真正要问自己的不是“文件都建好了没有”，而是：

> 我现在手里的这套绿灯，到底证明了多少是真的，哪些地方还只是安静地看起来没问题。
