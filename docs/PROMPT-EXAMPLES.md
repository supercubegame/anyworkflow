# Prompt Examples

这份文件只放**新对话里实际该怎么开口**，不解释原理。原理去看：
- `docs/FULL-WORKFLOW.md`
- `docs/BOOTSTRAP-FROM-ZERO.md`

---

## 1. 第一次测试它会不会自己走进这套方法

### 目标
不给方法提示，只给足够像这个技能该接手的任务，看它会不会自己进入“先闸门后功能”的工作方式。

### 示例 1：网页小游戏
> 做个 2D 小游戏，自己把质量关好，我不想手动帮你验。

### 示例 2：简单网页工具
> 做个简单网页工具，功能别花哨，但要自己把交付质量关好。

### 示例 3：浏览器扩展
> 做个 Chrome 扩展原型，先把质量和验证链条搭好，再做功能。

### 不要在第一句就喂进去的话
先别主动写这些，不然你以后分不出是 skill 触发了，还是模型只是顺着你的原句做：
- 先搭验证闸门
- 返回退出码
- 回写 PR 评论
- attest
- 先闸门后功能

---

## 2. 当它第一次问项目类型 / 判据时，怎么回

### 网页小游戏
> 这是个 2D canvas 网页游戏。跑起来的最低判据：能构建、能自动打开页面、能拿到稳定退出码，基础玩法能被脚本验证。

### 静态网页工具
> 这是个静态网页工具。跑起来的最低判据：能构建、能打开页面、核心输入输出有自动验证、失败时 exit 1。

### 浏览器扩展
> 这是个 Chrome 扩展。跑起来的最低判据：扩展能加载、popup / content script / 背景逻辑能被验证、关键功能有自动化检查。

---

## 3. 当它开始要手动设置时，怎么确认

### 给权限
> 好，继续。需要我手动开的权限和页面，你一次说全。

### 要它先继续修红，不要回来问
> 继续盯 CI，红了就自己修。除非缺权限、缺凭据，或者你读不到关键结论。

### 要它顺手做部署
> 绿了以后把试玩部署也接上，但先保证验证链条是通的。

---

## 4. 当你要它补“闸门的闸门”时，怎么说

### 验证报告送达
> 回写通道也要验证。别只让闸门绿，得证明评论真的送达，而且带本次 SHA / run id。

### 心跳与 schedule
> 再给定时链路补心跳。手动验证和定时新鲜度要分字段，别让一次手动盖戳救活一条死掉的 cron。

### 负向证明
> 别只告诉我它会绿，故意改坏一次，看它会不会红。

---

## 5. 当你想测试 summary 自动触发时，怎么发

### 目标
不点名技能，不复述 skill 摘要原句，只给足够该触发的任务。

### 示例
> 做个 2D 小游戏，自己把质量关好，我不想手动帮你验。

### 你在看什么
- 它会不会先问项目类型和“跑起来”的判据
- 它会不会先搭 gate，再写功能
- 它会不会主动提回写、attest、心跳、盲区

### 你不能从这个结果直接得出什么
即使它做对了，也**不能直接证明** skill 是靠 summary 被成功加载的。它也可能只是模型自己想对了。

---

## 6. 当你要它停，不再扩面时

> 先停。别再加新测试，也别再补新机制。现在只收口，把已经跑通的东西记成证据。

这句值钱，因为这套系统很容易滑向“给尺子加尺子”。

---

## 一句话提醒

**提示词只负责把问题抛对，不负责替它设计方法。**
你喂得越多，后面越难判断它到底是 skill 触发了，还是只是在顺着你复读。
