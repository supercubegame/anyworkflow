# 完整工作流程

## 这套东西到底在做什么
它不是“AI 写代码”这么简单。它是一个闭环：

1. 用户提出需求
2. 技能被匹配并加载
3. 先搭验证闸门，再写功能
4. CI 自动运行并把结果写回 AI 读得到的地方
5. AI 读取证据，先查尺子，再查夹具，最后才改产品
6. PR 绿后合并，外部观察者继续巡检

## 为什么顺序不能反
如果先写功能、后搭闸门，第一次跑起来时会同时红产品、夹具、阈值、回写，
你根本分不出是谁弄坏的。先有闸门，后面每一步才有验证依据。

## 真正的软肋
不是项目类型，是沉默通道：
- 回写失败
- cron 静默停用
- 台账自洽但不为真
- 抄本不是真身
- 整文件替换把该有的东西静默抹掉

## 外部观察者为什么存在
因为有些事仓库内部永远断言不了：
- 技能有没有真的靠 summary 被加载
- 其它仓库此刻是不是还是那样
- prompt 里那段散文在别的仓库改动之后还真不真
