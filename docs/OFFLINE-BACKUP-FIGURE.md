# 离线备份方案示意图（文字版）

## 标题
Agent 自验证流水线：离线备份方案示意图

## 副标题
抄本、真身、台账与外部观察者

## 这张图要表达的一句话
这套备份系统并不试图假装一切都是机器可验证的。相反，它把真身、抄本、台账、运行时真表和外部观察者分开，承认自动化边界，然后把“哪些东西还只能靠人或外部证据”明确写出来。它真正防的不是丢文件，而是**安静地说谎**。

## 四层结构

### 第一层：真身
这是 live truth。

包括：
- GitHub 仓库
- ClickUp Skills
- Super Agents
- Schedules
- PR / commit comments
- Pages
- heartbeat 文件

这些对象会真实变化，而且很多变化不会主动喊。它们是世界本身，不是说明书。

### 第二层：抄本
这是闸门实际能读到的东西。

包括：
- skills markdown
- agent JSON
- workflow files
- docs
- exported prompts

这层很重要，因为机器多数时候只能核对这里。**但抄本不是真身。** 抄本可以和台账完美自洽，同时跟真身一起过时。

### 第三层：台账与运行时真表
这是让备份“不敢装没事”的那一层。

包括：
- manifest 分片
- merge-manifest 合表
- nonempty-guard
- verified_against_live
- cross_repo
- writeback ledger

它的职责不是“证明一切都真”，而是：
- 让当前登记值带期限
- 让空数组、丢字段、没更新的台账会红
- 让“做完了还挂着”也会红

### 第四层：外部观察者
这是系统外的眼睛。

包括：
- Quinn
- Devon
- 人工截图
- 外部时间戳
- 真仓库读回

这层存在的原因很简单：有些真值永远不在本仓库里。那就别假装本仓库能证明它。

## 三类最危险的坏法

### 1. 抄本不是真身
你能证明导出的 JSON 文件还在，不能证明 ClickUp 里现在还是那样。

### 2. 台账自洽不等于为真
内部几张表彼此对上，不代表外部世界没变。尤其是 cross-repo 这种结构，真值在别的仓库里。

### 3. 散文腐化
键还在，锚点还在，断言还绿，但某段解释的话已经不成立。最难的一类，是“已经被后文证伪的推断”，因为它没有字符串特征可抓。

## 哪些东西能守住

这张图里“能守住”的那些块，意思不是“它们证明世界为真”，而是“它们至少能让对应的坏法响起来”：

- 顶层键双向断言
- 锚点
- 新鲜度
- 心跳
- 非空守卫
- 回写送达 Attest
- cross-repo 读真文件

它们共同防的是：**结构还在、其实内容已经空了**，或者**结果存在、其实没人读得到**。

## 哪些东西还只能靠人或外部证据

这部分必须显式写出来，不然读者会把一份绿报告误解成“全都备了、全都验证了”。

目前还只能靠人或外部证据的包括：
- summary 自动触发归因
- agent 的 UI-only 字段
- UI 工具清单的可见标签
- prompt 里的散文真假
- 其它仓库里的现状
- 解释性注释消失

## 为什么“解释性注释消失”也算盲区

因为断言还在，不代表方法论还完整活在当前文件里。

一个 72KB 文件被拆成 3900 字节跑手时，59 条断言可以一条不少，但“为什么那条断言存在、它以前怎么装饰过一次、为什么这个数字不是 off-by-one”这些东西可能只剩历史提交里还有。**仓库不会为注释消失而红。**

## 这套备份真正防的不是丢文件，而是安静地说谎

这句话是这张图的底部结论，也是整套方案最该留下的一句：

- 记录值要有期限
- 做完了还挂着也判红
- 一个当前没有输入的检查器不是装饰

## 这张图适合怎么用

它不是操作手册，也不是事故台账。

它最适合放在：
- 恢复演练说明前面
- 对外解释这套系统“到底备份了什么、没备份什么”时
- 任何需要提醒读者“不要把绿当成全能”的场合

一句话总结：**它是结构图，不是胜利图。**
