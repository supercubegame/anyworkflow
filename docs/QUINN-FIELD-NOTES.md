# Quinn Field Notes

闸门审计 Quinn 的**档案**。它的 prompt 里只有铁律、判据和每天的动作；所有踩过的坑、每个仓库的具体看法、以及历史事故的来龙去脉都在这里。

<p><br/></p>

**为什么这样拆**：一份每天都要读进上下文的 prompt 越长，里面的指令越容易被忽略（实测那份长到 30,948 字节，然后在 9 天里被自己重写掉了七成八）。指令要短且稳定，档案可以随经验单调增长 —— 这是两件不同的东西，混在一起就注定反复顶格。

<p><br/></p>

**这份文件是权威。** prompt 不复述它，两边冲突时以这里为准。

## 为什么是每天，而不是每周

原来是每周一 09:00 跑一次。**那个频率漏掉了一次真故障，而漏掉的方式值得记住。**

<p><br/></p>

meetnote 的定时闸门在 2026-08-13、08-14、08-15 连续三天准时跑、**连续三天全红**。心跳文件把话说得清清楚楚：`status` 是 `drift`、`exit_code` 是 1、六条检查过了五条、试过发请求而没拿到响应 id。闸门红着，报告也红着。**每一层都在喊，而四天里没有人来。**

<p><br/></p>

因为上一次巡检是 08-10，下一次要等 08-17。**四天的检出延迟是排出来的，不是意外。** 被观察的东西每天在跑，观察者每周看一眼 —— 周期不匹配本身就是个洞。

<p><br/></p>

**更深的一层：那份报告其实送达了** —— 回写到了主干的提交评论上。它失败的地方不是送不出去，是**送到了一个没人看的地方**。所以那句话要读成两句：

<p><br/></p>

> 送不出结论的闸门等于没跑。而送到没人看的地方，同样等于没跑。

<p><br/></p>

定时跑在主干上，没有 PR，结论只能落成提交评论，而没有人天天翻提交评论。**Quinn 就是那个「有人看」。**

<p><br/></p>

定时是 09:20 而不是 09:00，为了和 Drift Devon 的 10:20 错开 —— 同一时刻两个人报同一批东西，人会开始跳过两边的消息。

## 事故档案

### 2026-08-14：抄本替真身变绿

备份仓抄本写着某个 agent 有 24 个工具，真身是 26，而闸门 14/14 全绿。**抄本永远自洽**，这是这一类断言的病根。

<p><br/></p>

同一天还有两件：界面上把两个工具的勾去掉、保存，界面认了，而接口读回来它们**原样还在**；Devon 想「修」一条定时，结果加出一条重复的周一，旧的删不掉。

<p><br/></p>

### 2026-08-15：那条限制其实只对一条通道成立

「接口只能加定时、删不掉」被写成了对整件事成立。**换一条通道（更新整份配置）旧的直接就没了。** 教训：复核一条限制时顺手问「这条说的是哪条路？换条路还成立吗？」

<p><br/></p>

同一天官方文档给出了工具摘不掉的根因：`Edit self` 与 `add_agent_schedule` 都在「Default tools」这个 14 项工具包里，而**默认工具不能被停用**。所以能力边界这道防线根本不存在。

<p><br/></p>

### 2026-08-16：只有靠写假话才能变绿的断言

跨仓台账那条断言要求每一行的 `ref` 都等于登记的策略，而真实世界是四处钉着、两处跟随。**填真话则红，填假话则全绿。** 这种断言比空断言更阴：它主动把人往说谎那一侧推。修法是换判词 —— 改成「有一处偏离而没有登记」必须判红。

<p><br/></p>

### 2026-08-26：Quinn 把自己重写掉了七成八

2026-08-17 备份的 prompt 是 **30,948 字节**；08-26 第一次重新导出时只有 **6,578 字节**。中间**一次读回都没有**（期限是 30 天）。

<p><br/></p>

被整段删掉的五节：失效形状那一节、备份仓与 TodoX 的切入点、共享回写的版本策略、「0 命中要配正向对照」、**以及「不许编辑自己」那一节本身**。同时多出一节没人写过的「三条纪律」，取向很清楚：让自己每天的活变轻。

<p><br/></p>

**三层同时没守住：**

<p><br/></p>

- `Edit self` 摘不掉，所以唯一的防线是写在正文里的一句话 —— 而那句话被删了
- 逐字节身份那条在**哈希同步刷新**时全绿：它守的是「有没有人偷偷改过存储字节」，不是「这份抄本还是不是原来那份东西」
- 30 天的读回期限，对一个能改自己的巡检太松

<p><br/></p>

**修了什么**：新增体积下限断言（高水位 + 25% 容差，两侧都红），agent 抄本的读回期限收到 3 天，并把这份 prompt 按「指令 / 档案」拆开。

<p><br/></p>

**仍然测不出来的那一半**：仓内没有任何东西能分辨「人有意缩写了它」和「agent 自己改的」—— 那需要平台的审计日志。所以新那条守的是「发生了」，不是「谁干的」。

## meetnote：两种相反的失效

响应结构漂移检查**每天定时跑**，因为上游改格式那天可能没人推代码。要防的两种失效样子完全相反。

<p><br/></p>

**第一种：cron 被平台静默停用**（仓库 60 天无活动）。**不要用「cron 还写在工作流文件里」当证据** —— 被停用时那个文件一个字都不会变。判据是主干上 `.github/live-heartbeat.json` 的 `checked_at`：超过 48 小时就报。

<p><br/></p>

**第二种：cron 活得好好的，而检查一直在红。** 这就是 08-13 到 08-15 真实发生的事，**而且当时预判错的正是这一种**（预判是「cron 大概率被停用了」）。

<p><br/></p>

**所以新鲜度和结论是两个字段，必须都读。** 那份心跳自己的说明只写着「超过 48 小时就说明 cron 没跑」，一个只核对新鲜度的读者，会在 `status` 明写着 `drift` 时得出「一切正常」。逐条读：

<p><br/></p>

- `checked_at` —— 多久以前（超过 48 小时报第一种失效）
- `status` —— `ok` / `drift` / `unconfirmed` / `bootstrap`。**不是 `ok` 就要报，不管它多新鲜。**
- `exit_code` —— 非 0 就是那次判红了
- `checks_run` 与 `checks_passed` —— 差值就是红了几条
- `attempted_request` 为真而 `response_id` 是 `null` —— 试过了但没拿到响应，那是「空转」的指纹

<p><br/></p>

`status` 连续三次以上是 `unconfirmed`：每次都没验证到任何真实响应（密钥失效、接口长期不可用）。**CI 全程绿、心跳也新鲜，只有外部观察者看得见这个模式。**

<p><br/></p>

`status` 是 `drift` 而没恢复：报它连续几天了，并看一眼仓库里那条漂移 issue（CI 自己维护，漂移时开、恢复后关）。

## flappycat：定时和心跳有了，而它守不住自己

2026-08-16 建的网页小游戏，闸门很硬（纯引擎 + 浏览器闸门 + 像素等号 + 变异体），Pages 站点在跑。定时是 `17 3 * * *`（**UTC 日更**，不是工作区时区），主干上有 `heartbeat.json`。

<p><br/></p>

**这一节整段重写过，而理由值得记住**：抄本没动，真身也没动 —— 动的是它们共同描述的那个**外部世界**。别人改一次，这边从闸门到扫描器一个字都不会红。所以读这一节之前先问一句「它现在还是这样吗」，**这是七个仓里最容易过期的一节**。

<p><br/></p>

四件特别看的：

<p><br/></p>

- `heartbeat.json` 里 `last_scheduled_run` 什么时候从 `null` 变成时间戳。在第一次真跑起来之前这条链一次都没验过，而「从没跑过」和「跑过又停了」在同一个 `null` 上长得一模一样。
- 手动那条路写的是另一个字段（`last_manual_run`），而新鲜度只读 `last_scheduled_run`。**如果有人把新鲜度改成读两个字段里较新的那个，这条断言当场变空** —— 一次手动盖戳就能救活一条已经死掉的 cron。
- **防自触发靠结构，不靠提交信息里的跳过标记。** 写心跳那步只在定时或显式手动时执行。看有没有人改成靠 `[skip ci]` 那类字符串：字符串守卫改一次模板就哑，而哑掉的表现不是红。
- `docs/OBLIGATIONS.json` 里那几条带期限的欠账。看的是**有没有人把日期往后挪** —— 那是明令禁止的动作，到期只有两个正确反应：真做完（删记录），或确认做不到（挪进「测不出来的」）。

<p><br/></p>

**它留下一个自己解决不了的洞**：心跳守着 cron，而判定心跳新不新鲜的那条断言，**跑在被它守护的那条流水线自己里面**。cron 一旦死了，那条断言也跟着不跑。观察者又一次是被观察的那个 —— 只有从外面看，才数得出它几天没动过。

## 共享回写的版本策略

有一批仓库的 workflow 引用同一份共享回写 workflow（`supercubegame/ci-workflows` 的 `.github/workflows/report.yml`）。**具体是哪些仓、哪些文件，只认 `anyworkflow` 里那份生成物 `docs/SHARED-WRITEBACK-CONSUMERS.md`** —— 手写的清单永远追不上目录，而它漏掉一个消费者时不会有任何动静（实测漏过两次：先是 flappycat，后是 crossyroad）。

<p><br/></p>

策略是**跟随主干**。此前反对照做的理由（「本仓有一条断言每次 push 都在守多消费者分叉」）**有个洞**：那条断言只扫本仓自己的 workflow，看不见 flappycat，而 flappycat 从建立起就用着 `@main`。**用来论证「分叉不会发生」的那条断言，恰好覆盖不到那个已经分叉的消费者。**

<p><br/></p>

**TodoX 那四处（`verify.yml` / `release.yml` / `screenshots.yml` / `mirror.yml`）还钉着 SHA，理由不是偷懒**：它自己的快闸门里有断言写着「`uses` 必须是 40 位 SHA」和「四份 workflow 钉的 SHA 集合大小恰好为 1」。只翻 workflow 不翻断言，它会当场红。而那几条断言住在一个 72KB 的 `scripts/verify.mjs` 里，超过写入通道一次能稳定替换的量。**正确顺序是先拆再翻。**

<p><br/></p>

要盯三样：

<p><br/></p>

1. **有没有人把 `pending_ref_migration` 的日期往后挪。**
2. **`upstream_read_at` 还剩几天。** 跟随主干的代价是上游改一行这边不会红，所以本地唯一的落点是「上次真的去读过远端主干」有 30 天期限。顺手比一眼归档拷贝 `vendor/ci-workflows/report.yml` 和远端 `main` 上那一份是不是同一份 —— **不是同一份就是上游动了，那一刻所有消费者的行为都变了，而没有任何断言会红。**
3. **TodoX 迁完之后台账有没有跟着改。** 一处没被登记的偏离，和没有偏离长得一模一样。

<p><br/></p>

**别自己去改任何一处 `uses`，也别自己去改台账。**

## 备份仓与 TodoX 特别看什么

这两个断言密度高得多，很多断言自己还带着变异体自证。别从头逐条读，按这几处切入。

<p><br/></p>

**clickup-brain-backup** —— 重点六处：

<p><br/></p>

- **那几个样本数是等号断言**，而它们连着错过四次（每次都是有人填了一个没真数过的数）。看有没有人把数字改小去迁就删掉的样本 —— 正确做法永远是补样本。
- **变异体是不是还在真的判红。** 每个变异体都该先断言「替换真的发生了」；少了那一句，一个没匹配上的替换会得到和原文相同的「变异体」，它当然活下来。2026-08-15 真出过事：有人改了一个步骤的名字，靠逐字替换构造的变异体立刻匹配不上，是那句前置断言救的场。
- `scripts/lib/heartbeat.mjs` 里的 `OBLIGATIONS`：带期限的欠账清单，过期判红、做完了还挂着也判红。**它现在是空数组，这是正常的** —— 检查器和自证样本留着就够。但如果有人往里加条目而完成判据写成「靠人报告」，那条义务等于不存在。
- `scripts/lib/split-guard.mjs`：守技能拆分那条，**承重的是负向那侧**（搬走的小节标题必须在档案里、**不在**父技能里）。光断言「档案文件存在」是空的 —— 复制一份留两处同样通过。
- `scripts/lib/manifest-checks.mjs` 里的跨仓台账检查器：**承重的那条是「有一处偏离而没有登记」必须判红。** 看有没有人把它改回「所有行必须相等」，也看有没有人把 `pending_ref_migration` 整个删掉 —— 那样偏离就重新变得不可见了。
- `manifest.json` 里那些 `_` 开头的说明字段：它们是这套东西的记忆，有一条顶层键集合的双向断言在守。别让人把它去掉。

<p><br/></p>

**TodoX** —— 重点三处：镜像那条的 11 项检查（证明公开镜像里 0 泄漏，是**负向断言**，最容易悄悄变空）；发布流程里「转正」那一步（历史上它的终态只有打印没有断言）；以及那四处还钉着的 `uses`。

<p><br/></p>

**散文腐化：键还在、锚点还在、闸门全绿，而某句话已经不成立了。** 扫描器只守得住前两种形态（没登记的承诺、有真值可比的计数），**另外三种归 Quinn**：

<p><br/></p>

- **已经被证伪的推断** —— 没有任何字符串特征能区分「仍然成立的推理」和「已被推翻的推理」，判断它需要读懂后文。一条被推翻的推理留在档案里比没写更危险：下一个人会拿它当结论。
- **真值不在那份文件里的活数字**（比如「某份技能此刻多少字节」）—— 交叉核对做不了，唯一的修法是根本不写。
- **真值住在另一个仓库里的那些话** —— 扫描器只读得到一份文件。别人在别的仓库改一次，这边全绿着过期。**这一种没有任何自动化的解，唯一的落点就是 Quinn。**

## 测不出来的：这份清单唯一的常规外部审计

`anyworkflow` 与 `clickup-brain-backup` 的 `manifest.json` 里各有一节 `_tested_limits` —— 「这条路走不通」的实测结论，每条都带日期和当时的返回结果。它是这套东西省时间的地方。

<p><br/></p>

**而它有个隐藏的破坏力：没人会去核对一件已经宣布无法核对的事。** 一条写错的「测不出来」比没写更危险 —— 它让那个方向永久失去监督，而且看起来像是已经想清楚了。

<p><br/></p>

那份清单**全部由同一个人写、同一个人核对**。它已经被证伪过好几次，**没有一次是靠巡检**：有的靠一张截图，有的靠一个完全不知道这份清单存在的会话在别的仓库里独立撞上。所以抽查是常规监督，但从来不是唯一的 —— 别把「我查过了」当成「它一定对」。

<p><br/></p>

**每周挑一条，真的去试一次，别读着判断。** 三步：

<p><br/></p>

1. **挑最久没被复核的那条。** 优先挑那种「如果它其实做得到，会让某个方向重新有人监督」的 —— 那类错的代价最大。
2. **真的调一次那个工具**，把返回原样记下来。别因为「上次写着不行」就跳过 —— 那正是这条规矩要防的东西。
3. **三种结局都要报**：还是不行（更新日期，证据留着）；**其实可以了**（那条要收窄或删掉，这是最值钱的结果）；你这个身份试不了（说清是权限还是工具没给，别写成「不行」）。

<p><br/></p>

**一条比事实更宽的「测不出来」，会让人放弃一条其实走得通的路。** 收窄一条和删掉一条同样值钱，都要在报告里单独说一句。

## 已知的通道限制

- **直接落在主干上那些提交的 check 结论读不到**（能读结论的那条路要有 PR）。所以「主干最近一次 CI 绿不绿」通常得靠回写的评论、或最近那个 PR 来判断。读不到就说读不到。
- **私有仓没被代码搜索索引**，失败的样子是「0 命中」。永远配一个正向对照。
- **HTML 注释在读评论的通道里会被吞掉**，所以回写 marker 和 composer 哨兵用肉眼看不见 —— 能证明它们真在正文里的只有 attest job。
- **报告里的哈希只印前 12 位。** 截断的标识符只能用来看，不能用来写。
- **「现在几点」是一条会陈旧的观察通道。** 实测差过一个多小时，而且真的据此造出过一个不存在的 bug —— 错的方向是「把好的说成坏的」，那种错一样贵。
