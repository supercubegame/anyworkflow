# 恢复演练记录模板

## 这份模板的用途
这不是原理说明，也不是恢复步骤重写。
它只服务一件事：**当你真的恢复过一次时，怎么把那次演练记成一份以后还能读的账。**

一份没演练过的备份，不算备份。
一份演练过但没写清楚“到底验证了什么、没验证什么”的记录，也很快会退化成一句口号。

## 这次恢复了什么
逐项写，不要写“全部恢复成功”这种废话。

- [ ] 仓库 workflow 文件
- [ ] 共享 workflow 依赖引用
- [ ] 规则文件（AGENTS / CLAUDE）
- [ ] Skills 抄本
- [ ] Agent prompt 抄本
- [ ] 观察者 schedule
- [ ] heartbeat / attest / 回写链路
- [ ] 其它：

---

## 这次是怎么验证的
每一项都写“用什么证据确认”，不要写“已确认”四个字就完事。

| 项目 | 证据类型 | 证据内容 | 结论 |
| --- | --- | --- | --- |
| 示例：回写链路 | PR 评论读回 | marker 出现在本次评论里，带本次 SHA 和 run id | 通过 |
| 示例：schedule 真触发 | 外部时间戳 + heartbeat.json | `last_scheduled_run` 从 null 变成时间戳 | 通过 |
| 示例：agent prompt | live 读回 vs 抄本 | 逐字段 / 逐字比对 | 通过 / 不通过 |

证据类型只允许写这几类：
- 真文件读回
- live 配置读回
- 外部时间戳
- PR / commit 评论
- 截图
- 人工验收

---

## 这次仍然证明不了什么
这一节必须写，哪怕答案是“无新增”。

- 例：skill summary 自动触发
- 例：ClickUp UI-only 字段
- 例：prompt 里的散文在别的仓库改动后是否仍为真
- 例：解释性注释是否在多轮重写中丢失

写法要求：
- 说明为什么证明不了
- 说明以后靠什么补
- 不许写成“以后再说”

---

## 这次新发现的风险
只记这次演练新暴露的，不复述旧档案。

- 风险：
- 它为什么危险：
- 它当前有没有断言在守：有 / 没有
- 如果没有，后续是加断言、加台账、还是只能列 blind spot：
