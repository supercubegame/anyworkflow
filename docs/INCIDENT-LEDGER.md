# 事故台账

这份文件不讲“系统怎么设计”，只讲“它怎么坏过”。

## 1. 报告送不出来，但闸门是绿的
两条闸门都过了，回写 job 挂在拉代码那一步。提交页上一条评论都没有。
结论：**送不出结论的闸门等于没跑。**
修法：PR 评论 + commit 评论两条路都要通，attest 再回头确认评论真的出现。

## 2. heartbeats 自己也会变成沉默通道
定时 workflow 静默停用时，工作流文件一个字都不会变。没有带时间戳的正向痕迹，就分不出“没坏消息”和“已经死了”。
结论：**检查某个东西还在运行时，只有正向痕迹算数。**
修法：heartbeat.json + 外部观察者。

## 3. 抄本会替真身变绿
agent JSON 写着 24 个工具，真身已经是 26。闸门全绿，因为它核对的是抄本和登记表自洽。
结论：**抄本不是真身。**
修法：verified_against_live 加期限，逼人定期读回真身。

## 4. 台账自洽不等于为真
cross_repo 台账能写得很完整，但真文件在别的仓库里已经变了。本仓闸门一个字都不会红。
结论：**自洽不等于为真。**
修法：外部观察者去读真文件；完成后必须回写台账。

## 5. 整文件替换会静默抹掉东西
一次只想补一个括号，结果四个数组被清空。顶层键还在，所以顶层键断言全绿。
结论：**一条只看键在不在的断言，看不见一个被清空的数组。**
修法：拆大文件、非空守卫、分片合表。

## 6. 尺子也会说谎
正则把 `a === b` 当成小节标题，报告出来的是一个“看起来很像真问题”的计数。
结论：**产品没问题，说谎的是尺子。**
修法：给尺子配尺子，夹具自证必须常驻。

## 7. 解释性注释会消失，而断言可能还绿着
把 72KB 文件拆小之后，59 条断言一条不少，但不少“为什么这条存在”的说明只剩历史提交里还有。
结论：**断言还在，不等于方法论还完整活在当前文件里。**
修法：把最贵的解释沉淀进技能、台账、恢复文档；别让任何会常改的文件再长回 72KB。
