**送达核对（attest）不是装饰。**

它此前从没在 live CI 里红过一次。离线自证很硬（九个合成样本 + 四个变异体），但按这套方法自己的规矩：

## 二、attest 自己的一次真红

### 变异体
`.github/workflows/verify.yml` 里传给共享回写 workflow 的那一行 marker，多了两个字符：

```
marker: '<!-- anyworkflow-verify -->'    ->    marker: '<!-- anyworkflow-verify-x -->'
```

一个字符级的改动，一个文件。

### 实测结果（run `32911142277`，提交 `048e6b4`）

| job | 结论 |
| --- | --- |
| `备份仓闸门` | **failure**（8/10） |
| `回报结果` | **failure** |
| `核对结论真的送达了` | **failure** |

闸门是**单点命中**，两条，其余八条没有陪葬：

- `回写 marker：workflow 与 manifest 逐字相同`
- `承重文件逐字节身份（blob 哈希）` — `verify.yml：期望 82f816240698 实际 1d7475cc2760（5219 bytes）`

## 三、这次红为什么比预期值钱

预期是「attest 找不到评论所以红」。**实际发生的比那个阴得多。**

改歪 marker 之后，回写**仍然贴出了评论**，只是贴在新 marker 下（新建一条）。于是 PR 上同时存在两条：

| 评论 | marker | 正文说什么 |
| --- | --- | --- |
| `#5418393988`（23:31:46 新建） | 带 `-x` | 本次真报告：`048e6b4` · run `32911142277` · **8/10 有失败** |
| `#5417728064`（23:13:47 最后更新） | 原 marker | 上一轮留下的：`ac76179` · run `32909793880` · **10/10 全部通过** |

attest 从 `manifest.writeback.marker` 读它要找的标记（那是真源），所以它找到的是**后者**。

也就是说：**「存在一条带 marker 的评论」这个条件成立了。**

> 如果 attest 只断言到这一层，它会当场变绿 —— 而它读到的那份写着「10/10 全部通过」，来自一个完全不同的提交。闸门明明是红的，而那条陈旧评论会告诉我一切安好。

这就是幂等写入假绿的教科书形状，而它刚刚真的发生了一次。

**承重的是那两条钉在本次运行上的断言**：正文必须同时含本次短 SHA 与本次 run id。这一轮是它们的首演，而它们拓住了。

### 顺带一条：它不是侥幸

attest 跑了 **48 秒**（`23:31:52` → `23:32:40`），也就是 8 次轮询全部用尽，每一次都判失败。不是某一次时序上的碰巧。
